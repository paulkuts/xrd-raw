# Валидация xrd-raw: методика, набор фикстур и тесты

Документ описывает **независимый** контур проверки научной корректности
идентификации фаз (исполнитель D). Научные выводы и числа — в
[`docs/SCIENTIFIC_VALIDATION.md`](SCIENTIFIC_VALIDATION.md).

## 1. Что и зачем проверяется

Программа обещает пользователю: «по пикам дифрактограммы определить
кристаллические фазы образца». Проверяемый контур поэтому узкий и жёсткий:

```
.raw (WinXRD) → winxrd2xy.parse → peakpick.pick → phases.explain → список фаз
```

Проверяется:

1. **Полнота** (recall): каждая фаза, реально присутствующая в образце,
   должна попасть в результат.
2. **Точность** (precision): фазы, которых в образце нет, не должны
   выдаваться как кандидаты. Ложное определение хуже пропуска — так
   сформулирован приоритет проекта.
3. **Отсутствие ложной уверенности**: при недостатке данных (одна линия,
   узкий диапазон, слабый набор) результат обязан быть скромным, а не
   «FOM 76 — значит фаза».
4. **Устойчивость к шуму и фону**: число ложных пиков не должно расти как
   «потолок max_peaks».
5. **Диагностика сдвига**: сдвиг 2θ должен обнаруживаться, когда он есть, и
   не выдумываться, когда его нет.
6. **Поведение при неверной длине волны**: результат должен ломаться
   (или требовать подтверждения излучения), а не давать случайную фазу с
   высоким FOM.

Не проверяется (зона других исполнителей): экспорт XLSX/TXT/графики
(ветка C), устойчивость парсера к битым файлам (ветка B), алгоритмическая
реализация скоринга (ветка A). Здесь только измеримые последствия для
научного результата.

## 3. Методика

### 3.1 Независимая истина

Позиции пиков в фикстурах считаются из **литературных** межплоскостных
расстояний d (PDF 46-1045 кварц, 05-0586 кальцит, 33-0311 гипс, 44-1481
портландит; эттрингит — Handbook of Mineralogy) по закону Вульфа—Брэга.
База `tools/phases_db.json.gz` при генерации **не используется** — иначе
тест проверял бы базу саму на себя.

Единственное исключение — `dft_weak` (фаза есть только в расчётной базе
JARVIS-DFT, литературного набора линий для неё не существует). Для неё
рефлексы взяты из базы, и это помечено в `truth.present[0].line_source`.

Истина записывается в JSON рядом с `.raw`: состав, сдвиг, σ шума, параметры
фона, фактическая длина волны, seed, ожидаемое поведение
(`expect_no_confident_candidate`).

### 3.2 Критерий «фаза найдена»

Фаза считается найденной, если запись базы удовлетворяет **двум** условиям:

1. **Набор отражений**: не менее 60 % истинных линий с I ≥ 10 % имеют
   рефлекс базы в пределах 0.25° по 2θ (сравнение по d, не по названию —
   в базе гипс зовётся и `CaSO4*2H2O`, и `CaH4SO6`, кварц — `Quartz low`
   и `SiO2`);
2. **Химия**: набор элементов записи совпадает с формулой истинной фазы.

Второе условие обязательно. Без него любая случайная многолинейная
структура «покрывает» 2 из 3 линий кварца: на фикстуре с неверной длиной
волны запись `DyGe3` давала 2 попадания из 3 и формально считалась
«кварцем». Это проверено и зафиксировано в коде теста.

### 3.3 Метрики (`tests/benchmark_xrd.py`)

| метрика | определение |
|---|---|
| `recall` | найдено истинных фаз / всего истинных фаз (по всем фикстурам) |
| `precision` | (кандидатов − ложных) / кандидатов; ложный = не совпал ни с одной истинной фазой |
| `line_recall` | истинных линий, у которых есть пик в пределах 0.20°, / всего истинных линий в диапазоне (I ≥ 3 %) |
| `spurious_peaks` | пиков дальше 0.20° от любой истинной линии |
| `unexplained` | пиков, не отнесённых explain() ни к одной фазе (только I ≥ 3 %) |
| `t_parse`, `t_pick`, `t_explain` | секунды на полной базе 32 491 фаза |

Метрики считаются только на синтетике с известной истиной. Абсолютные
значения FOM не сравниваются между фазами — FOM это «оценка совпадения»,
не вероятность (см. CONTRACT §1.4).

### 3.4 Что считается провалом

- истинная фаза отсутствует в результате (recall);
- в результате есть фаза, которой в образце нет (precision);
- уверенный кандидат (FOM ≥ 55, статус candidate) на данных, которых
  недостаточно (одна линия, 4 линии, чистый шум);
- ложных пиков больше, чем истинных линий (шумовой спектр);
- сдвиг «найден» на несдвинутом образце или не найден на сдвинутом.

## 4. Как воспроизвести

```bash
cd <корень репозитория>

# тесты (Linux, venv; на Windows — python\python.exe)
/root/work/.venv/bin/python -m unittest tests.test_regression -v

# бенчмарк: таблица в консоль + JSON
/root/work/.venv/bin/python tests/benchmark_xrd.py --out tmp/bench.json

# один сценарий
/root/work/.venv/bin/python tests/benchmark_xrd.py --only mix_qcg --out tmp/mix.json

# медленная проверка сдвига по ПОЛНОЙ базе (~65–85 с)
XRD_SLOW=1 /root/work/.venv/bin/python -m unittest tests.test_regression -v

# пересобрать фикстуры (детерминированно)
/root/work/.venv/bin/python tests/fixtures/make_fixtures.py
```

Требования: только стандартная библиотека + numpy. Сеть не нужна. Временные
файлы — в `tempfile.mkdtemp()`. Реальные образцы не изменяются.

Фактическое время на сервере (2 ядра, параллельно работают другие агенты):
тесты **23–55 с**, бенчмарк **33–53 с** — разброс целиком от загрузки машины,
не от кода. `estimate_shift` на полной базе в тестах пропускается:
82 с на вызов.

## 5. Состав набора

9 синтетических образцов (подробно — `tests/fixtures/README.md`):

| фикстура | сценарий | истина |
|---|---|---|
| `quartz_pure` | одиночная фаза | кварц |
| `mix_qcg` | смесь трёх фаз | кварц + кальцит + гипс |
| `overlap_calcite_gypsum` | перекрытие 3.035 / 3.06 Å | кальцит + гипс |
| `noise_slope` | слабый сигнал, наклонный фон | кварц 260 имп. на фоне 1160→60 |
| `shift_plus010` | сдвиг 2θ | кварц + кальцит, +0.10° |
| `narrow_20_35` | узкий диапазон 20–35° | гипс + портландит (сильные линии вне) |
| `wrongwl_co_as_cu` | неверная λ | Co Kα, метаданные «Copper» |
| `noise_only` | шум + 1 посторонний пик | фаз нет |
| `dft_weak` | 4 линии расчётной фазы | NbN (JARVIS-DFT) |

Плюс реальный образец `/root/work/samples/261007115241.raw` — используется
**только на чтение** как контроль «живых» данных; в тестах не участвует
(2600 точек, 4.02–56°, слабый сигнал, максимум 173 имп.).

## 6. Статус тестов на текущем коде (baseline «ДО»)

38 тестов: **23 ok**, **8 expected failure**, **7 skipped**. Подробная
таблица «сценарий → статус → причина» — в
`docs/SCIENTIFIC_VALIDATION.md`, раздел 3.

Кратко:

- проходят: одиночная фаза, перекрытие (обе фазы найдены), отсутствие фаз
  на чистом шуме, обнаружение сдвига +0.10° и невыдумывание сдвига,
  «одна линия — не кандидат», поломка при неверной λ, штраф DFT,
  индексы в пространстве полного списка, рендер отчёта;
- проваливаются (expectedFailure): трёхфазная смесь (0 из 3), гипс в узком
  диапазоне, штраф за линии вне диапазона (28.2 балла FOM), 120 пиков на
  чистом шуме, кварц на наклонном фоне, уверенные кандидаты на 4 линиях;
- пропущены до ветки A: `flags`, `status`, `n_ref_out_of_range`,
  `peak_status`, `shift_mode`, `peak_id/snr/wavelength` в пиках,
  `per_peak` в формате контракта §4.

## 7. Правила для ведущего при интеграции

1. **expectedFailure — это заявка на исправление, а не «так и надо».**
   Если после слияния ветки A тест с `@unittest.expectedFailure` начал
   проходить, unittest покажет `unexpected success` — декоратор надо снять,
   тест становится обычным зелёным.
2. **skipped-по-возможностям включаются сами.** Проверки полей контракта
   гейтятся наличием поля в результате (`_install_contract_skips`), ничего
   править не нужно.
3. **Порог `min_fom=55` зафиксирован в тестах намеренно** — это дефолт
   продукта. Если ветка A изменит дефолт, менять надо и тесты, и
   `docs/SCIENTIFIC_VALIDATION.md`.
4. **Фикстуры не подгонять под новый код.** Если фаза «нашлась» только
   после правки истины в JSON — это подгонка; правильный путь — правка
   алгоритма или честное понижение статуса теста.
5. **Числа «ПОСЛЕ»** заполняются повторным прогоном бенчмарка:
   `tests/benchmark_xrd.py --out tmp/bench_after.json`, таблица переносится
   в `docs/SCIENTIFIC_VALIDATION.md` §2.

## 8. Ограничения методики (важно)

1. **Синтетика ≠ реальный цемент.** В фикстурах нет дублета Kα₁/Kα₂,
   осевой расходимости, асимметрии пиков, аморфного гало C-S-H, текстуры,
   микроабсорбции и преференциальной ориентации портландита/гипса.
   Реальные соотношения интенсивностей могут отличаться в 2–3 раза.
2. **Шум гауссов, а не пуассонов.** Реальный счёт имеет σ = √N; на слабом
   сигнале (максимум 173 имп.) это качественно меняет картину. Фикстура
   `noise_only` калибрована по σ реального образца, но не по его
   корреляциям.
3. **Эталонные интенсивности — справочные, не измеренные на этом приборе.**
   Совпадение d проверяется строго, интенсивности — мягко (вес 0.40 в FOM).
4. **Критерий идентичности фазы (60 % линий + химия) — эвристика.**
   Полиморфы с близкими наборами линий (кальцит/арагонит/ватерит) им не
   различаются надёжно; для них нужен отдельный тест по различающим линиям.
5. **`estimate_shift` в тестах проверяется на мини-базе** (4 фазы), иначе
   82 с на вызов. Полная база — только под `XRD_SLOW=1`.
6. **Метрики не нормированы на сложность образца.** 33 линии в `mix_qcg`
   против 7 в `narrow_20_35` — сравнивать recall между фикстурами нельзя,
   только агрегат.
7. **Отсутствует количественный анализ.** Рентгеновская фазовая
   идентификация не даёт процентов; совпадение интенсивностей в FOM не
   является количественным определением.

## 9. Что осталось непроверенным

- поведение на **реальных** многокомпонентных цементных образцах (нужен
  набор измерений с независимым XRD/Rietveld-заключением);
- различение политипов и полиморфов (арагонит/кальцит/ватерит, C₃S
  M1/M3) — фикстур нет;
- аморфная составляющая и её вклад в фон;
- Kα₁/Kα₂ дублет и его влияние на ширину/положение пиков;
- текстура и преференциальная ориентация (портландит, гипс, слоистые);
- экспорт (TXT/XLSX/графики) — зона ветки C;
- устойчивость парсера к битым/чужим файлам — зона ветки B;
- точность `estimate_shift` на реальной юстировке (эталонный образец
  нужен физически).
