# Контракт результата и владение файлами (для параллельной работы)

Версия контракта: 1.0 (20.10.2026). Ведущий агент: Warden. Исполнители A–D.

## 1. Неприкосновенные правила

1. Файлы пользователя (`input/*.raw`, любые реальные образцы) — только чтение. Тестовые
   прогоны — на копиях в `tmp/` или `tests/fixtures/tmp/`. Никаких `git reset --hard`,
   `git clean -fd`, force push.
2. Портативность Windows: минимум NumPy, Matplotlib, openpyxl. **SciPy обязательным
   не делать.** Тесты — на `unittest` (stdlib), запускаются и в embeddable Python.
3. Обратная совместимость: имена выходных файлов, позиции меню и публичные сигнатуры
   сохраняются; новые параметры — только kwarg-ами с дефолтами.
4. FOM — «оценка совпадения», не вероятность. Количественный состав не заявлять.

## 2. Единый источник излучения — `tools/radiation.py` (готов, владелец: ведущий)

```python
rad = radiation.Radiation.from_settings(meta, anode=None, model=None)
rad.lam               # длина волны, Å (по умолчанию Cu Kα средневзвешенная 1.54184)
rad.anode, rad.model  # 'Cu', 'ka_avg' | 'ka1'
rad.source            # 'user' | 'metadata' | 'default'
rad.confirmed         # подтверждён ли анод (не «предположение»)
rad.describe()        # строка для отчёта: «Cu Kα ..., λ = 1.5418 Å; источник: ...»
rad.d(two_theta)      # d, Å
rad.ref_two_theta(d, ref_two_theta=None)  # позиция эталона в текущем излучении (пересчёт ПО d)
rad.matches_base()    # совпадает ли с длиной волны базы (1.54184)
```

Правила:
- Любая функция, считающая d или сравнивающая с эталоном, принимает `radiation` (объект)
  **или** `wavelength` (float) kwarg-ом. Дефолт — Cu Kα средневзвешенная (как база).
- `tools/peakpick.py` больше не хранит свою константу: `CU_KA = radiation.BASE_WAVELENGTH`
  оставить как алиас для совместимости.
- `tools/winxrd2xy.py::d_spacing(two_theta, wavelength=None)` — дефолт из radiation.
- Позиции эталонов в `phases.py` всегда пересчитываются через `rad.ref_two_theta(d)`.
- Строка излучения обязательна в TXT-отчёте, на графике и в листе «Сводка» XLSX.

## 3. Идентичность экспериментального пика

- Пики — `list[dict]`, порядок = возрастание 2θ, индексы **стабильны** и присваиваются
  один раз в `peakpick.pick()`.
- Каждый пик получает: `n` (1-based номер, = index+1) и `peak_id` (= index, 0-based).
- `phases.explain()` / `search_phases()` **всегда возвращают индексы в пространстве
  исходного полного списка пиков**, даже если внутренне фильтруют слабые пики.
  Внутренняя фильтрация — через явную карту `obs_index -> peak_index`.
- Запрещено опираться на `id(dict)` или на порядок после фильтрации.

## 4. Структура результата `phases.explain()` (совместимая + расширенная)

```python
{
  "phases": [ {                      # ровно как раньше + новые поля
      "phase": {...},                # запись базы
      "fom": 78.3,                   # оценка совпадения (0..100), НЕ вероятность
      "fom_raw": 86.3,
      "cov_ref": 0.66, "cov_obs": 0.31,
      "key_hits": 2, "key_total": 3,
      "n_matched": 5, "n_ref": 9,        # n_ref = только рефлексы В ДИАПАЗОНЕ скана
      "n_ref_total": 12,                 # всего взято сильнейших в эталоне
      "n_ref_out_of_range": 3,
      "mean_dtheta": 0.08,
      "matched": [(ref_index, peak_index, dtheta), ...],   # peak_index — ПОЛНЫЙ список
      "explained_peaks": [peak_index, ...],                # ПОЛНЫЙ список
      "share": 0.42,
      "status": "candidate" | "ambiguous" | "weak",        # подтверждение пользователя отдельно
      "datasource": "COD" | "JARVIS-DFT",
      "prior": ["building_materials"] | [],
      "flags": ["FEW_DIAGNOSTIC_LINES", "NO_STRONG_LINE", ...]
  }, ...],
  "per_peak": { peak_index: [ {"phase_no": 1, "dtheta": 0.03, "ref_int": 100.0,
                              "overlap": False|True}, ... ] },
  "unassigned": [peak_index, ...],          # в пространстве ПОЛНОГО списка
  "ambiguous": [peak_index, ...],           # пики, на которые претендуют >=2 фазы
  "peak_status": { peak_index: "assigned"|"ambiguous"|"unexplained"|"below_threshold" },
  "elements": {"Ca": ["CaCO3"], ...},
  "n_obs": 14,                              # сколько пиков участвовало в поиске
  "n_peaks": 120,                           # сколько было передано
  "shift": 0.0,
  "shift_mode": "auto"|"manual"|"off",
  "shift_gain": 0.0,
  "radiation": {...},                       # rad.as_dict()
  "settings": {...},                        # tol, min_fom, min_obs_int, профиль, db_filter
  "db_meta": {...}
}
```

Ключевые требования:
- Один экспериментальный пик **может** принадлежать нескольким фазам. Никакого
  взаимоисключающего назначения: `_score_phase` при финальном пересчёте не «занимает» пик
  монопольно (см. п.5).
- `unassigned` и `per_peak` — в индексах полного списка, согласованы с
  `format_report`, `make_graph`, `make_xlsx` без пересчётов на стороне потребителей.
- Пики, не участвовавшие в поиске (I < `min_obs_int`), получают `below_threshold` и
  **не считаются** «необъяснёнными».

## 5. Алгоритм (A) — требования, не реализация

1. **Предварительный отбор** быстрый (индекс по углу) — оставить.
2. **Финальная привязка** — совместная для выбранных фаз: для каждого пика собираются все
   кандидаты-рефлексы в пределах `tol`; пик помечается `ambiguous`, если претендуют
   >=2 фаз. Фаза не «исчезает» из-за того, что её линии заняла другая фаза.
3. **Скоринг**: рефлексы эталона ограничиваются диапазоном скана
   `[2θ_min - tol, 2θ_max + tol]` (после поправки сдвига) и ранжируются по I.
   `n_ref` = число попавших в диапазон; штраф за пропущенные сильные линии — только
   по линиям в диапазоне. Если в диапазоне меньше 2 диагностических линий —
   `flags += ["FEW_DIAGNOSTIC_LINES"]`, фаза помечается «недостаточно данных» и не может
   получить статус candidate без подтверждения пользователя.
4. **Штрафы**: необъяснённые сильные эталонные линии в диапазоне — штраф;
   JARVIS-DFT — штраф и `datasource`; `prior` (профиль) — мягкий бонус к ранжированию,
   не фильтр, и всегда помечается в отчёте.
5. **Сдвиг**: режимы `off` / `manual` / `auto`. По умолчанию `auto` с малым span
   (<= 0.2°), порогом выигрыша (>= 8 %) и требованием записать применённую поправку
   в отчёт. Автосдвиг — диагностика юстировки, не «подгонка» под фазу.
6. **Тесты** (`tests/test_phases.py`) обязаны покрыть: слабый пик перед сильным
   (индексы), двухфазную смесь с общими пиками, узкий диапазон 2θ с линиями эталона
   вне его, отрицательный контроль (случайное совпадение одной линии), пустой спектр.

## 6. Пик-пикинг (B) — требования

- Обработка для детекции отделена от исходных данных: исходная кривая не изменяется,
  все производные кривые — только внутри функции.
- Адаптивные пороги: prominence/height привязаны к оценке шума (MAD σ), а не к доле от
  максимума, иначе шум даёт десятки ложных пиков (на реальном `261007115241.raw`
  текущий код выдаёт 120 пиков при ~14 значимых).
- Контракт `pick(...)` сохраняется: `two_theta`, `d`, `intensity`, `height`,
  `prominence`, `fwhm`, `n`; добавляются `peak_id`, `snr`, `wavelength`.
- Парсер `.raw`: устойчивость к чужим/битым файлам (ValueError с понятным текстом),
  проверка шага, дубликатов 2θ, минимальное число точек; `.xy/.csv` пишутся как раньше.

## 7. Графики и отчёт (C) — требования

- Тема `paper` (светлый научный стиль) как дополнительная; `dark` не ломать.
- Верх — исходная (несглаженная) кривая; пики помечаются по 2θ; Bragg-штрихи внизу
  отдельными полосками по фазам с кодами `Q`, `C`, `G`, `P`, ... расшифровка в легенде.
- `?` — только для реально необъяснённых пиков; неоднозначные помечаются отдельно
  (`?*` или подписью «кандидат/перекрытие»).
- Лимит — только на количество подписей (не на данные): не более ~12 подписей,
  приоритет — сильные пики и подтверждённые фазы.
- PNG >= 300 dpi, SVG векторный, опция «чистый график без фаз».
- TXT и XLSX используют ТОЛЬКО структуру из п.4 (никаких пересчётов индексов),
  указывают излучение, режим сдвига, источник базы, SHA-256 исходного файла,
  статусы `candidate/ambiguous/unexplained`, ограничения метода.
